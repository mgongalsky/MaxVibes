# Step 10 — Manual smoke test

## Цель

Убедиться, что фича работает end -to - end в реальном IDE : переключение в Claude Code режим → отправка сообщения → получение ответа → Approve → применение модификации → IDE - restart с восстановлением сессии .

## Pre - requisites

-`claude` CLI установлен и работает(проверить: `claude --version` в терминале)
-API key для Claude настроен в `claude` CLI (как обычно — через `claude /login` или env
var )
-В `MaxVibesSettings` указан корректный путь к `claude`(или дефолтный `claude` если в PATH)
-`testVibes` или другой тестовый проект открыт
        -Все шаги 1–9 выполнены, сборка зелёная

## Чек - лист

### Сценарий 1 — первый round -trip без файлов

1.Открыть testVibes в run -IDE
2.Открыть MaxVibes tool window
        3.Создать новую сессию чата
        4.В UI переключиться в режим * * Claude Code * *(4 - я опция)
5.Отправить простое сообщение: «Привет, скажи hello world»
6.* * Ожидаемо:** в течение 30 секунд приходит ответ, в чате видно ASSISTANT message
7.* * Проверить в логах * *(idea.log или MaxVibes log): `claude` процесс запустился, observed sessionId извлёкся
8.* * Проверить в `ps aux | grep claude` * *(Linux / macOS) или Task Manager (Windows): процесс жив

### Сценарий 2 — round - trip с requestedViews

1.В той же сессии отправить: «Расскажи что в файле `src/main/kotlin/Main.kt` — сначала запроси его»
2.* * Ожидаемо:** Claude Code присылает ответ с `requestedViews` для Main . kt; в UI появляется кнопка * * Approve * *
3.Нажать * * Approve * *
        4.* * Ожидаемо:** в чате появляется новое USER - сообщение(
    системное,
    с прикреплёнными файлами
) и следующий ASSISTANT -ответ с описанием файла
        5.Кнопка Approve пропадает

### Сценарий 3 — модификация(auto - apply)

1.Отправить: «Добавь в Main.kt функцию `fun greet(name: String) = "Hello, \$name"` — модифицируй файл »
2.* * Ожидаемо:** Claude Code присылает ответ с `modifications`; модификация применяется автоматически
3.* * Проверить:** в IDE Main.kt действительно изменился, добавилась функция
        4.* * Проверить:** commit dialog показывает предложенный commitMessage

### Сценарий 4 — plan - only режим

        1.Включить чекбокс « Plan only» в UI
        2.Отправить: «Перепиши Main . kt с использованием классов»
3.* * Ожидаемо:** Claude Code присылает discussion в `message`, `modifications` пустой, файл не меняется

### Сценарий 5 — IDE restart с resume

        1.После Сценария 3 — закрыть проект (или перезапустить IDE)
2.Открыть проект снова, выбрать ту же сессию чата
3.Отправить новое сообщение: «Покажи что у нас в текущем диалоге»
4.* * Ожидаемо:** Claude Code продолжает контекст (помнит про Main.kt); в логах видно `claude --resume <id>` или эквивалент
        5.* * Если resume не сработал : * * в логах видно fallback на полный контекст; диалог продолжается, контекст послан полностью

### Сценарий 6 — переключение режимов туда - обратно

1.Переключиться из Claude Code в Clipboard
        2.* * Ожидаемо:** кнопка Approve пропадает, появляются Copy JSON / Paste Response
        3.Отправить сообщение через Clipboard — работает как обычно
        4.Переключиться обратно в Claude Code
5.* * Ожидаемо:** UI правильно отражает текущий статус Claude Code сессии (если она была)

### Сценарий 7 — error handling

        1.В настройках указать неверный путь к `claude`(например, `/nonexistent/claude`)
2.Отправить сообщение в Claude Code режиме
        3.* * Ожидаемо:** в чате появляется error -сообщение «Claude Code binary not found», UI не падает
4.Восстановить путь, повторить — работает

### Сценарий 8 — закрытие проекта убивает процесс

        1.Запустить Claude Code сессию (Сценарий 1)
2.Запомнить PID процесса(`ps aux | grep claude`)
3.Закрыть проект в IDE
        4.* * Ожидаемо:** процесс claude больше не существует(`ps aux | grep <pid>` пусто)

-[] Сценарии 6–8 пройдены
        -[] `RESULTS.md` создан и заполнен
-[] Все обнаруженные баги либо пофикшены, либо записаны в `docs/TODOs/`
