# Planner — Feature Plan

## Цель

Встроенный * * планнер в чате * * : закреплённая (pinned) сворачиваемая панель с планом текущей задачи и чекбоксами по шагам.Модель создаёт план, по мере выполнения подзадач « тикает » чекбоксы и идёт дальше.План связан с нашим подходом к документации: ссылка на общий `PLAN.md` фичи и на `STEP_N.md` конкретного шага открываются прямо в редакторе .

## Ключевые решения

| # | Решение | Обоснование |
|---|-------- - |------------ - |
| 1 | План живёт в `ChatSession.plan` (persisted) | Переживает рестарт IDE; у каждой ветки диалога свой план; переиспользуем существующий persistence - стек |
| 2 | Модель управляет планом через новое опциональное поле `plan` в JSON -ответе | Единый механизм для CLAUDE_CODE и CLIPBOARD режимов — протокол общий |
| 3 | **Snapshot - семантика * *: поле `plan` полностью заменяет текущий план | Идемпотентно, не нужен diff - протокол; модель просто присылает актуальное состояние |
| 4 | `docPath` у плана и у каждого шага — опциональные ссылки на `docs/features/<X>/PLAN.md` / `STEP_N.md` | Консистентность с нашим документационным подходом; клик открывает файл в редакторе |
| 5 | Ручной toggle чекбокса юзером разрешён | Персистится сразу; актуальное состояние плана уходит модели в следующем запросе — модель видит правку |
| 6 | UI - панель монтируется между хедером и conversation, collapsible | Всегда на виду(pinned), но сворачивается в одну строку с прогрессом `3/7 ✓` |
| 7 | Статусы шагов : `PENDING` / `IN_PROGRESS` / `DONE` / `SKIPPED` | IN_PROGRESS подсвечивает текущий шаг; SKIPPED — осознанный пропуск, не ломает прогресс |

## Что переиспользуется

        -`ChatSession` + `ChatSessionRepository` + persistence — план просто новое поле сессии.
-`JsonInteractionProtocolCodec` — декодирование нового поля ответа .
-`ChatPanelState` → `ChatPanel.render()` — стандартный путь доставки состояния в UI .
-Механика навигации по клику (как `ccLogLink` / `ChatNavigationHelper`) — для открытия doc - файлов.

## Что строится новое

1.* * Domain:** `TaskPlan`, `PlanStep`, `PlanStepStatus`; поле `plan` в `ChatSession` +`withPlan()`.2.* * Протокол:** поле `plan` в `InteractionResponse`, константы схемы, толерантный декодер .
3.* * Services:** `ClaudeCodeInteractionService` и `ClipboardInteractionService` персистят план из ответа; актуальный план включается в исходящий запрос .
4.* * UI:** `PlanPanel`(
    pinned,
    collapsible,
    чекбоксы,
    прогресс,
    ссылки на доки
).5.* * Wiring:** `ChatPanelState.plan`, монтирование в `ChatPanel`, обработчики toggle / навигации .
6.* * Prompt:** инструкции в `claude-code-system.md` и `chat-system.md` — как и когда вести план.

## Definition of Done всей фичи

-Модель присылает `plan` в ответе → панель появляется над чатом, pinned и collapsible.
-По мере выполнения шагов модель обновляет статусы → чекбоксы тикаются автоматически.
-Клик по названию плана открывает `PLAN.md`, клик по шагу — его `STEP_N.md` (если docPath задан).
-Ручной toggle чекбокса персистится и виден модели в следующем запросе .
-Рестарт IDE восстанавливает панель из персиста сессии.
-Unit - тесты зелёные на `./gradlew :maxvibes-application:test` и `:maxvibes-domain:test` .
-Smoke test из `STEP_8_SmokeTest.md` пройден.
