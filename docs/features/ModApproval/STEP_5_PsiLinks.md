# Шаг 5 — PSI - ссылки в тексте сообщений

## Цель

LLM ссылается на элементы кода прямо в тексте; клик ведёт к элементу в редакторе .

## Конвенция(промпт)

Обычная markdown -ссылка, адрес = существующий element path:

`[UserService.validate()](file:src/main/kotlin/com/example/User.kt/class[User]/function[validate])`

Для файлов — просто `file:<путь>`.В промпты : «упоминая функцию / класс / файл, оформляй первое упоминание такой ссылкой». Новый синтаксис не вводим — переиспользуем формат путей модификаций, LLM его уже умеет писать.

## Изменения

1.Промпты chat -system.md / claude - code - system.md: раздел с конвенцией + примеры.2.Проверить, что prose -сегменты(
    `buildSegmentsPanel`
) создаются через `MarkdownRenderer.createPane` с `onLink → onNavigateToPath` (по javadoc — да; если нет, подключить).
3.Fallback уже есть: `ChatNavigationHelper.navigateToElement` возвращает статус - строку — битый путь даёт сообщение в статусе, без исключений .

## Acceptance

-Ссылка на существующую функцию открывает её в редакторе .
-Битый путь показывает статус « не найдено», UI остаётся живым.
