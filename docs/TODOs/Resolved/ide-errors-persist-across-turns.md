# IDE ошибки сохраняются между сообщениями без явного прикрепления

## Проблема

Когда пользователь прикрепляет IDE -ошибки к одному сообщению (кнопка «Attach IDE Errors»),
они продолжают присутствовать в последующих запросах, даже если пользователь их
        больше не прикрепляет и не запрашивает .

## Воспроизведение

1.Пользователь нажимает « Attach IDE Errors » — ошибки прикрепляются к первому сообщению.2.Пользователь отправляет следующее сообщение * * без * * прикрепления ошибок.3.В отправленном JSON всё равно присутствует поле `ideErrors` с теми же ошибками из предыдущего шага.

## Причина

`ClipboardSessionState.ideErrors` и `ClipboardInteractionService` сохраняют `ideErrors`
в состоянии сессии при первом вызове `startTask`.При вызове `continueDialog` поле
        наследуется из предыдущего состояния, если явно не передан `null`:

```kotlin
sessionState = state.copy(
    attachedContext = attachedContext ?: state.attachedContext,
    ideErrors = ideErrors ?: state.ideErrors   // ← null не сбрасывает!
)
```

Если `continueDialog` вызывается без `ideErrors`(т.е.с `null`), оператор `?:`
        подставляет старое значение из состояния, вместо того чтобы очистить поле.Аналогичная проблема возникает с `attachedContext`.

## Последствия

-LLM получает устаревшие ошибки, которые пользователь не намеревался отправлять.
-Увеличивается размер payload без пользы — лишние токены .
-LLM может неверно интерпретировать контекст и предлагать исправления уже
решённых проблем .

## Возможные решения

### Вариант A — Sentinel -значение для сброса(минимальное изменение)

Ввести явный сигнал «очистить поле », например пустую строку вместо `null`:
```kotlin
ideErrors = ideErrors ?: state.ideErrors
// заменить на:
ideErrors = if (ideErrors != null) ideErrors.ifBlank { null } else state.ideErrors
```
Но это усложняет семантику .

### Вариант B — Явный флаг `clearErrors: Boolean` в `continueDialog`

        Добавить параметр, который явно сбрасывает поле :
```kotlin
suspend fun continueDialog(
    message: String,
    ideErrors: String? = null,
    clearErrors: Boolean = true,   // по умолчанию сбрасывать
    ...
)
```

### Вариант C — Ошибки не хранить в состоянии сессии(рекомендуется)

IDE - ошибки — это контекст * * конкретного сообщения * *, а не всей сессии .
Правильнее не сохранять их в `ClipboardSessionState` между ходами,
а передавать только в тот запрос, к которому они явно прикреплены:
```kotlin
// В generateAndCopyJson:
ideErrors = state.ideErrors   // ← убрать из state, передавать напрямую
```
То же самое относится к `attachedContext` .

## Статус

Открыто.Рекомендуется Вариант C как наиболее архитектурно чистый.
