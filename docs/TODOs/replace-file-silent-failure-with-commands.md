# REPLACE_FILE: молчаливый провал применения при комбинировании с commands

**Статус:** зафиксировано, воспроизведено один раз
**Дата:** 2026 - 07 - 20
**Компоненты:** maxvibes - plugin / PsiModifier(REPLACE_FILE), пайплайн apply -then - run - commands

## Симптом

Один ответ LLM содержал `REPLACE_FILE` для `maxvibes-plugin/build.gradle.kts` * * плюс * * `commands`
(git add +git commit).Плагин отчитался об успешном применении и запустил команды, но:

-git commit вернул `nothing to commit, working tree clean`;
-проверка диска (`Select-String`) показала * * старое * * содержимое файла — правка не применилась;
-никакого сигнала об ошибке ни пользователю, ни LLM .

Повторная отправка * * того же * * `REPLACE_FILE` в следующем ходе, уже без `commands`,
применилась нормально (коммит d54a680).

## Гипотезы причины

        1.* * Порядок сохранения : * * правка применяется к Document / PSI в памяти, но
`FileDocumentManager.saveAllDocuments()` не вызывается(или вызывается после)
запуска прикреплённых команд — внешний процесс git видит старый файл на диске .
Не объясняет, почему файл остался старым и при последующей проверке .
2.* * Тихое исключение в PSI -пути для `.kts`:** Gradle - скрипт — это KtFile -скрипт,
а не обычный KtFile; REPLACE_FILE мог упасть внутри write action, а исключение —
проглочено.Тогда «успех» в отчёте — ложный .
3.Комбинация 1 + 2: провал применения не проверяется перед запуском команд.

per - modification результат (applied / failed + причина) в следующий запрос LLM;
-Принудительный `saveAllDocuments()` * * до * * запуска `commands`;
