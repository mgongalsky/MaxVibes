# TODO: Сообщать LLM о файлах, которые не были найдены

## Проблема

Когда LLM запрашивает файлы через `requestedFiles` и один или несколько из них не существуют
        в проекте (неверный путь, файл удалён, опечатка в имени), плагин молча их пропускает .

LLM получает JSON - запрос без части ожидаемого контекста и не знает об этом .
В результате :
-LLM может повторно запросить тот же несуществующий файл в следующем раунде
-Пользователь не получает никакого предупреждения
-Диагностировать проблему сложно

## Воспроизведение

1.Clipboard - режим, LLM запрашивает `requestedFiles: ["path/to/NonExistent.kt"]`
2.`ClipboardInteractionService.gatherRequestedFiles()` вызывает `contextProvider.gatherFiles()`
3.Файл не найден — результат тихо игнорируется или возвращается пустая строка
4.JSON - запрос к LLM формируется без секции с этим файлом
5.LLM не получает никакого объяснения

## Желаемое поведение

        В JSON -запросе к LLM должна присутствовать секция с информацией о ненайденных файлах.Варианты реализации :
-Добавить поле `"missingFiles": ["path/to/NonExistent.kt"]` в `ClipboardRequest`
-Или включить явное упоминание в `systemInstruction` / `current_message` :
`"Note: the following requested files were not found: ..."`
-Также показывать предупреждение в UI(системный бабл или статус)

## Где смотреть

        -`ClipboardInteractionService.gatherRequestedFiles()` — место где файлы собираются
        -`ClipboardRequestBuilder.build()` — где формируется итоговый JSON -запрос
-`ClipboardRequest` — доменная модель запроса(куда добавить поле `missingFiles`)
-`contextProvider.gatherFiles()` — возвращает `Result`, нужно анализировать какие пути не вернулись

## Приоритет

Средний — пользователь замечает проблему только при отладке сложных диалогов .
