# Context gatherer: дедуп молча выбрасывает requestedViews

**Статус:** РЕШЁН — 2026-07-27 (основной сценарий; одно старое наблюдение перепроверить, см. ниже)
**Дата:** 2026-07-05
**Компонент:** `ClipboardInteractionService.gatherRequestedFiles` / `ClaudeCodeInteractionService.gatherRequestedFiles`

## Симптом (историческое)

`requestedViews` с `path`, уже числящимся в собранных файлах сессии, молча выкидывались из payload:

- LLM не получал ни содержимого файла, ни маркера, что view отфильтрован
- Повторный запрос того же файла не помогал
- Список собранных путей персистится в состоянии сессии, поэтому в рамках сессии файл был недоставляем

LLM либо зацикливался на повторных запросах, либо писал код по памяти. Прошлая сессия PyCharm-фичи была закрыта именно из-за этого бага.

## Корень и фикс

В обоих `gatherRequestedFiles` дедуп-ветка `requestedPaths.filter { it !in state.allGatheredFiles }` собирала только новые пути и возвращала только их — уже собранные либо выпадали из выдачи (этот баг), либо отдавались из устаревшего сессионного кэша (`protocol-full-view-stale-content.md`).

Фикс 2026-07-27: ветка удалена, ВСЕ запрошенные пути всегда перечитываются через `contextProvider.gatherFiles(requestedPaths)` и все попадают в выдачу. `allGatheredFiles` остался только учётом для `previouslyGatheredPaths`.

## Осталось перепроверить

Наблюдение 2026-07-17 (сессия EditorActions): из батча выпал в том числе НОВЫЙ для сессии путь (`SkillManagerDialog.kt`), что чистым path-дедупом не объяснялось; дословный повтор батча следующим ходом доставил всё. Если после фикса подобный дроп целого батча повторится — это отдельный баг, диагностировать заново (смежные: `protocol-multiple-views-same-file-not-delivered.md`, `missing-requested-files-feedback.md`).
