# Context gatherer: дедуп молча выбрасывает requestedViews

**Статус:** открыт — только задокументирован, НЕ чинить в рамках PyCharm-фичи
**Дата:** 2026-07-05
**Компонент:** clipboard-протокол, сбор контекста (previouslyGatheredFiles)

## Симптом

`requestedViews` с `path`, уже числящимся в `previouslyGatheredFiles` сессии, молча выкидываются из payload:

- LLM не получает ни содержимого файла, ни маркера, что view отфильтрован
- Повторный запрос того же файла не помогает
- Смена `granularity` не помогает — дедуп идёт только по path
- Список `previouslyGatheredFiles` персистится в состоянии сессии, поэтому в рамках сессии файл недоставляем навсегда

## Последствия

LLM либо зацикливается на повторных запросах, либо вынужден писать код по памяти. Прошлая сессия PyCharm-фичи была закрыта именно из-за этого бага.

## Наблюдение 2026-07-17 (сессия EditorActions) — одиночное, требует перепроверки

Батч из двух view: `FileSpecificPromptRepository.kt` (FULL; путь уже собирался в первом ходе как SIGNATURES) и `SkillManagerDialog.kt` (SIGNATURES; путь для сессии НОВЫЙ). Доставлен не был ни один — в payload пришёл только `docs/ARCHITETURE.md`, присутствовавший в контексте с первого хода (вероятно, глобальный контекстный файл). Дословный повтор того же батча следующим ходом доставил ОБА файла, включая FULL по ранее собранному пути.

Что это уточняет относительно описания выше:
1. Дроп может зацепить весь батч, а не только дедупнутый путь: новый для сессии `SkillManagerDialog.kt` тоже не доехал. Возможно, совпадение с другим сбоем — одно наблюдение.
2. «Недоставляем навсегда» выполняется не всегда: здесь ретрай сработал, в том числе со сменой granularity. Либо условия дропа сложнее чистого path-дедупа, либо в первом ходе отработал другой фильтр.

При фиксе перепроверить оба пункта.
