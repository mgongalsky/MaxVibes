# PSI-правки не сбрасываются на диск — команды и проверки читают устаревший файл

**Статус:** РЕШЁН — 2026-07-27 (решение A реализовано)
**Компонент:** `PsiCodeRepository.applyModifications`

## Симптом (историческое)

После применения батча модификаций (PSI) shell-команды из поля `commands` читали содержимое файла **с диска** и видели состояние *до* правок. Модель делала ложный вывод, что модификации молча не применились. Два инцидента за одну сессию (2026-07-27, рефакторинг ChatMessageController):

1. Греп-проверка сразу после DELETE-батча из 16 элементов «показала», что все элементы на месте → модель повторила удаления → повторный батч упал, потому что элементы уже были удалены (в буферах IDE).
2. Подсчёт LOC с диска дал 1126 строк, тогда как в IDE файл уже был 655 строк.

## Причина

Модификации применяются через PSI и живут в Document-буферах IntelliJ до момента сохранения (компиляция, autosave, потеря фокуса). Команды выполняются обычным процессом из корня проекта и видят только диск. Между «применено» и «сохранено» — окно в минуты.

Родственная, но другая проблема: `protocol-full-view-stale-content.md` (там — устаревший сессионный кэш при FULL-вью; здесь — устаревший диск при живых буферах). Обе решены.

## Решение

**A (реализовано).** `PsiCodeRepository.applyModifications` после батча с хотя бы одним `ModificationResult.Success` вызывает `flushDocumentsToDisk()` → `invokeAndWait { FileDocumentManager.saveAllDocuments() }`. Команды, грепы и внешние инструменты сразу видят применённое состояние. Точка одна и покрывает все три режима (API / Clipboard / Claude Code).

**B (протокольное правило для модели — оставить как страховку).** Не доверять чтению с диска в том же ходу, где были `modifications`; расхождение «IDE говорит одно, диск — другое» трактовать в пользу IDE.
