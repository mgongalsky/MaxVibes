# Autonomy budget : считать LLM - итерации вместо внутренних действий

## Контекст

Сейчас `AutonomyBudget` расходуется на отдельные автоматические действия автопилота : `VIEW_REQUEST`, `MODIFICATION`, `COMMAND`, `CONTINUATION` и другие разрешённые шаги.Из - за этого исследование кода через несколько последовательных views может исчерпать лимит, хотя модель фактически выполнила значительно меньше автономных итераций .

По логам эффект стабильно воспроизводится: после пользовательского сообщения выполняется ровно 12 автоматических действий, после чего следующее действие требует ручного Approve.Ручной Approve не восстанавливает бюджет, поэтому после исчерпания лимита каждое следующее действие снова останавливается на approval.Новое пользовательское сообщение создаёт новый цикл и возвращает бюджет.Это внутреннее ограничение MaxVibes, а не внешний rate limit Claude .

## Требуемое поведение

### 1.Новая единица бюджета

Бюджет должен означать количество автономных запусков следующей LLM -итерации, а не количество внутренних действий.

-Одна автономная передача управления модели без нового сообщения пользователя расходует одну единицу .
-`VIEW_REQUEST` сам по себе не расходует отдельную единицу .
-Автоматическое применение `MODIFICATION` не расходует отдельную единицу.
-Автоматически разрешённые `COMMAND`, `BUILD` и `TESTS` не расходуют отдельную единицу.
-Approval policy по - прежнему независимо определяет, можно ли автоматически выполнить конкретное действие .
-Расход бюджета должен происходить в одной очевидной точке — при запуске следующей автономной LLM -итерации / continuation.
-Несколько requested views или modifications в одном ответе модели не должны уменьшать бюджет несколько раз.Пример: лимит `12` означает до 12 автономных обращений к модели после пользовательского запуска, независимо от количества views, modifications и commands внутри этих итераций .

### 2.Настройка бюджета в основной панели

Добавить управление лимитом непосредственно в панель автономного режима .

-Показывать текущий заданный лимит автономных LLM -итераций.
-Позволять менять лимит без перехода в отдельные Settings .
-Значение должно сохраняться в настройках и использоваться для новых / восстановленных циклов .
-UI должен ясно называть единицу измерения, например `Autonomous iterations` / `LLM iterations`, чтобы значение не воспринималось как число файлов или действий.
-Определить допустимый диапазон, валидацию и значение по умолчанию.
-Желательно отображать оставшийся бюджет текущего цикла, если это не перегружает панель.

### 3.Поведение после исчерпания бюджета и ручного Approve

Когда бюджет закончился и действие остановилось для ручного подтверждения:

-Если auto mode включён, ручной Approve должен восстановить бюджет до настроенного лимита и запустить новый автономный цикл.После одобренного действия работа должна снова продолжаться автоматически до следующего исчерпания бюджета или завершения задачи.
-Если auto mode выключен, Approve остаётся одноразовым разрешением только текущего ожидающего действия . Автономный цикл не включается и бюджет не должен неявно запускать дальнейшую автоматическую работу .
-Ручной Reject не должен восстанавливать или запускать автономный цикл.
-Поведение должно быть одинаковым для view, modification, command, build, tests и continuation, если они остановились именно из - за исчерпания бюджета.
-Нужно отличать остановку из -за бюджета от остановки из - за approval policy: обычный ручной approval не должен случайно сбрасывать бюджет, если budget exhaustion не был причиной паузы.

## Дополнительная проверка

        После добавления action kinds `BUILD` и `TESTS` проверить исчерпывающие `when` в `TurnAutopilot` и связанных мапперах / оркестраторах.Новые kinds должны корректно обрабатываться approval policy, но не расходовать отдельные единицы нового iteration budget .

## Тестовые сценарии

        1.Один ответ модели запрашивает 5 views : расходуется максимум одна единица только при следующем автономном запуске модели, а не пять единиц .
2.Ответ содержит несколько modifications : их количество не влияет на iteration budget .
3.Автоматические command / build / tests проходят по policy и не списывают дополнительный budget .
4.При лимите 3 после пользовательского сообщения возможны ровно 3 автономные LLM - итерации, затем следующая останавливается.5.При исчерпанном бюджете и включённом auto mode ручной Approve восстанавливает полный настроенный лимит и автономная работа продолжается.6.При исчерпанном бюджете и выключенном auto mode ручной Approve выполняет только текущее действие; следующий шаг снова требует участия пользователя .
7.Reject не восстанавливает бюджет .
8.Изменённое в панели значение сохраняется и применяется к следующему циклу .
9.Изменение лимита во время активного цикла имеет явно выбранную и протестированную семантику : либо обновляет только следующий reset, либо корректирует текущий remaining budget.10.`BUILD` и `TESTS` не приводят к ошибке в исчерпывающем `when(action)` .

## Критерии готовности

        -Budget списывается ровно один раз за автономную LLM -итерацию.
-Количество views / modifications / commands внутри итерации не влияет на budget .
-Лимит редактируется непосредственно в панели и сохраняется.
-Ручной Approve после budget exhaustion восстанавливает цикл только при включённом auto mode .
-При выключенном auto mode Approve остаётся одноразовым.
-Поведение покрыто unit - тестами доменной логики, оркестратора / autopilot и тестами UI state / settings, где это применимо.
