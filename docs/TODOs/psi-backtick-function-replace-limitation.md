# PSI: невозможность REPLACE_ELEMENT для функций с backtick-именами

## Проблема

При попытке применить `REPLACE_ELEMENT` к тестовым функциям с именами в backtick-нотации
(пробелы и спецсимволы в имени, стандарт для Kotlin-тестов) PSI-адаптер не находит элемент:

```
Element not found: file:.../ClipboardMinimalModeTest.kt
/class[ClipboardMinimalModeTest]
/function[startTask always sends full context regardless of addHistory]
```

Максимум что удаётся — заменить весь класс через `REPLACE_ELEMENT` на уровне класса,
либо переписать весь файл через `REPLACE_FILE`. Оба варианта дорогостоящие по токенам
и опасны при больших тестовых файлах.

## Воспроизведение

Любой `REPLACE_ELEMENT` с путём вида:

```
file:...Test.kt/class[MyTest]/function[my test with spaces in name]
```

возвращает `Element not found`, даже если функция существует и имя указано точно.

## Уточнение 2026-08-16: ломается операция замены, а не разбор пути

В одной сессии подтвердились сразу три факта, которые сужают поиск:

1. `ELEMENT`-view по backtick-пути **работает**: запрос
   `class[ClaudeCodeResponseHandlerTest]/function[modifications commands and commit message are held together]`
   вернул полное тело функции.
2. `CREATE_ELEMENT` с `position: AFTER` по такому же backtick-пути **работает**: функция
   с пробелами в имени успешно послужила якорем для вставки нового теста.
3. `REPLACE_ELEMENT` по тому же виду пути **не работает** — две попытки подряд в
   `AgentTurnOrchestratorTest.kt` не применились целиком.

Значит путь парсится корректно и элемент находится: гипотеза из раздела «Причина»
про потерю backtick-обёртки при разборе сегмента `function[...]` этим опровергается.
Искать нужно в самой операции замены, а не в навигации.

## Отдельная проблема: отказ молчаливый

Батч не применился **полностью**, при этом агент не получил ни ошибки, ни признака
частичного применения. О провале стало известно только со слов пользователя, а
фактическое состояние файла пришлось выяснять отдельным запросом сигнатур.

Это опаснее самого ограничения: агент считает правку применённой и строит на ней
следующие шаги. Нужен явный отрицательный результат применения модификаций, доходящий
до агента следующим ходом — так же, как это сделано для POST-APPLY ERRORS.

## Причина (предположение)

Kotlin PSI представляет backtick-функции как `KtNamedFunction`, где `name` содержит
сырой идентификатор с backtick-символами. С учётом уточнения выше проблема, вероятно,
не в поиске элемента, а в замене: новый текст функции парсится фабрикой элементов и
либо не образует валидный `KtNamedFunction` с backtick-именем, либо результат замены
отбраковывается валидацией перед записью.

## Последствия

- Точечные правки в тестовых файлах с backtick-функциями невозможны через `REPLACE_ELEMENT`.
- Приходится использовать `REPLACE_FILE` или `REPLACE_ELEMENT` на уровне всего класса,
  что увеличивает расход токенов и риск затронуть несвязанный код.
- Переименование такой функции недоступно даже как замена в месте объявления.

## Возможные решения

1. **Проверить фабрику элементов**: убедиться, что текст `fun \`name with spaces\`()` даёт
   валидный `KtNamedFunction`, и что именно возвращает операция замены при отказе.
2. **Нормализация имени**: при поиске элемента сравнивать `name` без backtick и без
   учёта регистра.
3. **Альтернативная адресация**: поддержать адресацию по номеру строки или по
   аннотации (`@Test`-индекс) как запасной механизм для тест-функций.
4. **Явная диагностика**: возвращать агенту причину отказа применения, чтобы молчаливый
   откат батча перестал выглядеть как успех.

## Статус

Открыто. Обходное решение — `REPLACE_FILE` или `REPLACE_ELEMENT` на уровне класса.
