# CREATE_FILE не создаёт отсутствующие директории (тихий сбой)

**Статус:** открыт
**Обнаружен:** при записи планов фич в новые папки `docs/features/<Name>/`

## Симптом

Когда модификация `CREATE_FILE` указывает путь, родительская директория которого
ещё не существует, файл не создаётся. Ошибка при этом наружу не отдаётся — ответ
выглядит успешным, но файла на диске нет.

## Как проявилось

При создании `docs/features/ClaudeCodeToolExec/PLAN.md` папки `ClaudeCodeToolExec/`
не существовало. Файл не записался, ошибки не было. Пришлось вручную создать
директорию, после чего запись прошла успешно.

## Репро 2026-07-17 (сессия EditorActions — самое показательное)

Батч из 8 `CREATE_FILE`: стартовые скиллы в
`maxvibes-plugin/src/main/resources/skills/<id>/SKILL.md`. Ни одной из восьми
директорий не существовало (включая промежуточную `skills/`). Результат: «Applied
approved modifications», ноль файлов на диске, ноль ошибок. Обход: LLM запросил
через канал `commands` один PowerShell `New-Item -ItemType Directory -Force` со
всеми восемью путями, пользователь подтвердил, после чего файлы были доставлены
повторно и легли штатно. Вывод: масштаб не меняет поведение — 1 файл или 8 одним
батчем, сбой одинаково тихий.

## Влияние

- Планы и пошаговые доки (`docs/features/<Feature>/PLAN.md`, `STEP_*.md`) молча
теряются, если папка фичи ещё не создана.
- То же затрагивает любой `CREATE_FILE` в новые поддиректории
(`docs/refactors/<Name>/`, `docs/TODOs/Resolved/`, ресурсы плагина и т.п.).
- Особенно коварно из-за отсутствия ошибки: расчёт на то, что файл записан, —
а его нет.

## Ожидаемое поведение

Одно из двух (первое предпочтительно):
1. Перед записью файла создавать все недостающие родительские директории
(аналог `mkdirs`), затем писать файл.
2. Как минимум — возвращать явную ошибку вида «директория не существует: <path>»,
чтобы сбой был виден, а не гасился молча.

## Обходной путь (пока не исправлено)

Создать директорию до записи файла: вручную или командой `New-Item`/`mkdir`,
которую LLM может запросить через канал `commands`.

## Где, вероятно, чинить

`PsiCodeRepository.createFile` → `findOrCreateDirectory` / `createDirectoryPath`
(maxvibes-adapter-psi). Судя по репро, создание недостающих сегментов не
срабатывает для путей глубже одного отсутствующего уровня (или для целевых
директорий вне source root), а null-результат резолва глотается без
`ModificationResult.Failure`. Убедиться, что (а) все недостающие сегменты
создаются внутри write command, (б) невозможность создать директорию превращается
в явный Failure с сообщением.
