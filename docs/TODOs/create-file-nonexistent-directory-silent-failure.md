# CREATE_FILE не создаёт отсутствующие директории(тихий сбой)

**Статус:** открыт
**Обнаружен:** при записи планов фич в новые папки `docs/features/<Name>/`

## Симптом

Когда модификация `CREATE_FILE` указывает путь, родительская директория которого
ещё не существует, файл не создаётся.Ошибка при этом наружу не отдаётся — ответ
        выглядит успешным, но файла на диске нет.

## Как проявилось

        При создании `docs/features/ClaudeCodeToolExec/PLAN.md` папки `ClaudeCodeToolExec/`
не существовало . Файл не записался, ошибки не было.Пришлось вручную создать
директорию, после чего запись прошла успешно.

## Влияние

-Планы и пошаговые доки (`docs/features/<Feature>/PLAN.md`, `STEP_*.md`) молча
теряются, если папка фичи ещё не создана .
-То же, вероятно, затрагивает любой `CREATE_FILE` в новые поддиректории
        (`docs/refactors/<Name>/`, `docs/TODOs/Resolved/` и т.п.).
-Особенно коварно из - за отсутствия ошибки: расчёт на то, что файл записан, —
а его нет.

## Ожидаемое поведение

        Одно из двух(первое предпочтительно):
1.Перед записью файла создавать все недостающие родительские директории
        (аналог `mkdirs`), затем писать файл.2.Как минимум — возвращать явную ошибку вида «директория не существует: <path > »,
чтобы сбой был виден, а не гасился молча .

## Обходной путь (пока не исправлено)

Вручную создать директорию до записи файла в неё .

## Где, вероятно, чинить

Код применения модификаций, обрабатывающий `CREATE_FILE` (слой plugin — обработчик
        модификаций / файловый writer).Убедиться, что перед созданием файла отрабатывает
создание родительских папок и что путь сбоя(нет папки / нет прав) сообщается
        наверх, а не проглатывается.
